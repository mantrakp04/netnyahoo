# Speed, 0.2.23 → 0.2.24

The 0.2.24 release gate, 2026-10-03: the 0.2.23 export against the 0.2.24 export (built from 4638e701, the app as at
c1765497), one Apple Silicon Mac, hidden instances, both apps interleaved run by run in one `native-bench.mjs` process
(docs/perf/README.md). Medians, with min–max and the number of runs. Both apps share NATIVE_API_VERSION 6 and ran the
same bench bundle (built from 0.2.24's tree, kept in `dist/0.2.24/bench/`), so only native code differs. The bench
copies were signed without a secure timestamp (Apple's timestamp server was failing about 1 request in 6 that day).

The first attempt ran while another session's debug build was capturing at ~90% CPU and was discarded; the round
below waited for a quiet machine. In it, idle wakeups with 20 tabs and a new tab's first frame separated slightly
(28.5 → 29.2 /s, 84 → 90 ms, n=2); a second interleaved round of those rows with 4 runs (second table) overlaps on
both. The release passed: the same or better everywhere.

What 0.2.24 changes isn't in these rows: the profile-switch fix is measured in c6f22035 (per-switch cost flat over a
burst instead of growing, about half the main-thread work per sidebar switch), the toolbar's in 9be7a86e.
