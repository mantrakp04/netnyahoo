# 0.2.31 → 0.2.32 release gate

0.2.32 is 0.2.31 with one engine change (520605bb, no platform policy provider): its `main.jsbundle` is byte-for-byte
0.2.31's, and its Chromium framework (UUID 4C4C4487) is the one measured below as "fix", in 0.2.31's export, stripped
and signed as release.sh does. So the gate is that build against 0.2.31's export, measured on 2026-10-09 on a quiet Mac
(the raw results were in /private/tmp and went with a restart; the medians are kept here).

`native-bench.mjs --only launch --launch-runs 10`, interleaved:

| Median (range, n=10) | 0.2.31 | 0.2.32 |
|---|---|---|
| launch: window | 456 ms (411–511) | 449 ms (415–491) |
| launch: window with content | 475 ms (433–545) | 476 ms (430–526) |
| launch: JS | 347 ms (309–391) | 334 ms (302–362) |
| launch: first page painted | 531 ms (483–581) | 520 ms (486–588) |
| launch: first frame | 493 ms (451–552) | 487 ms (448–553) |

Same or better throughout, within noise. Under load (League running, n=8–14) the change measured ChromeMain →
BrowserMain 148 → 136 ms, and main-thread samples in PolicyLoaderMac::Load went 11.5 → 0 ms.

Against 0.2.30, the same build (quiet Mac, interleaved): launch window 464 → 482 ms, first frame 500 → 524 ms (n=12,
ranges overlap); idle with 1 and 20 tabs the same (20 tabs 1.37 → 1.28 %, 29.4 → 29.0 /s, n=5). js-bench (4 alternating
runs, 0.2.30 → 0.2.31's bundle): typing's worst key 13.0 → 7.6 ms; close20.taskMs 227 → 233 ms and hover24.taskMs
114 → 123 ms with separate ranges, the rest overlapping. 0.2.31's release gate showed idle with 20 tabs at 2.58 %; that
didn't reproduce.
