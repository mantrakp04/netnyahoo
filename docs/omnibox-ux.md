# Omnibox / command bar: Chrome's defaults vs Dia vs Netnyahoo

Audit of 2026-10-08. Not a spec: a map of what users expect from Chrome's address bar, what Dia does (Dia runs Chromium's
`AutocompleteController` behind its own Swift UI: its binary has `ArcAutocompleteMatch`, `autocomplete:cursorPosition:preventInlineAutocomplete:`,
`deleteAutocompleteMatch:`, `DeleteSuggestionView`, `SwitchToTabProvider`, and a text view tracking `backspacing`/`pendingBackspacing`, `handleMoveToRightEndOfLine`,
`classifyPasteAndGoInput`), and where our bar (`apps/browser/src/components/Omnibox.tsx`, `omnibox/*`, `packages/core/src/{suggest,omnibox,siteSearch}.ts`) differs.

Sources. Chrome 154 tree under `~/chromium-build/chromium_git/chromium/src`: `EM` = `chrome/browser/ui/omnibox/omnibox_edit_model.cc`,
`OV` = `chrome/browser/ui/omnibox/omnibox_view.cc`, `OVV` = `chrome/browser/ui/views/omnibox/omnibox_view_views.cc`, and `components/omnibox/browser/*`.
Dia: the owner's recording (`/tmp/nn-omni/f/003-014.png`, Dia) and the binary's strings; "?" = not observable from either.
Ours: line numbers are the working tree on 2026-10-08 (another agent was editing `inline.ts`, `suggest.ts`, `useSuggestions.ts`, `Omnibox.tsx`
for the Backspace fix at the same time; "HEAD" marks what the commit had).

How ours was checked: "pure" = node scripts over `packages/core` and `inline.ts` (`/tmp/nn-omni-audit/t*.mjs`); "live" = a hidden Debug instance
(`build-train` app, data dir `/tmp/nn-omni-audit-data`, quit afterwards) with real key events through `nn.shell.devTypeKeys`/`devKeyEquivalent` into the hero and panel bars,
and the omnibox dev driver for logic keys (`nn.omnibox.get(id).key(...)`). Synthetic `devTypeKeys` arrows/Tab/End do **not** reach RN's `onKeyDown` (they move the caret natively),
so keys marked "read" were checked by reading the code and by driving `onKeyDown` directly.

Status: ✅ compliant, ❌ gap, ⚠️ unsure or a deliberate Dia/Netnyahoo choice.

## Prioritized gaps

Order = most user-visible first. Each lists repro, expected, and the fix's files. Fixes #2, #3 and #4 overlap the Backspace fix in progress (`inline.ts` `fieldChange`, `Omnibox.tsx` `onChangeText`); `fieldChange` needs the field's selection from before the change for all three.
Caveat for any fix using `selection.current`: it goes stale after native or programmatic selects (live: after ⌘L the ref read 19-19 while the whole URL was selected), because `onSelectionChange` is not reliably delivered for them (`Omnibox.tsx:317`). Have `InlineCompletion.swift`/a new native read return the selection, or re-read it from the field when a change arrives.

1. **(Fixed 2026-10-08, `packages/core`) Trailing space keeps (or invents) an inline completion.** Repro (live, hero bar; history has github.com): type `git`, then Space. Field becomes `git hub.com` with `hub.com` selected, row 0 is GitHub, Enter opens GitHub. Pure: `buildSuggestions("git ")` → completion `hub.com`. Expected (Chrome `AutocompleteMatch::SetAllowedToBeDefault`, `scored_history_match.cc`): no completion once the input ends in whitespace, default row = search `git`. Fix: `packages/core/src/suggest.ts` `buildSuggestions`: `raw !== raw.trimEnd()` → `completes = false` and skip the `target && completion` branch (and the same `typedIsPage` rule as `preventInline`); test in `suggest.test.ts`. Also decide on leading space (` git` → field ` github.com`).
2. **⌫ after accepting the completion with → / End / ⌘→ brings the last character back.** Repro (live): type `git`, press →, press ⌫: `typed="github.co"`, field `github.com` with `m` selected. Expected: `github.co`, no completion, search row first (Chrome: accepting sets user text; ⌫ is `just_deleted_text`). Cause: `inline.ts:28` `typing` assumes a shorter field that starts with `typed` is typing over the completion; the accept is native and JS never hears of it. Fix: in `Omnibox.tsx` `onSelectionChange` (~317), when `shownCompletion` is set and the new selection is no longer exactly `[typed.length, value.length]`, accept it: `setTyped(value)`, drop the inline state (`useInlineCompletion` `setInline(null)`, `pending` cleared), `setSelected(0)`, which also re-queries rows for the accepted text (rows currently stay on `git`). Or give `fieldChange` the previous selection and call a collapsed caret at the end of `typed+shown` a deletion.
   **Fixed 2026-10-08:** `Omnibox.tsx` `onSelectionChange`: the caret collapsing at the end of `typed+completion` with no write in flight (`inline.ts` `acceptsCompletion`) makes the completion typed text and re-queries the rows. Live (real keys): `git`, → gives `typed=github.com`; ⌫ gives `github.co`, no completion; a one-character completion (`github.co`+`m`) typed over with `x` gives `github.cox`. End doesn't accept: on macOS it scrolls, the caret stays. Only the end-of-text collapse counts: Left/Home or the caret landing at the completion's start is also what Backspace/Delete over the selection produces, so they cannot be told apart from it.
3. **First keystroke after select-all / ⌘L is treated as a deletion when it is a prefix of the old text.** Repro (live): type `gi`, ⌘A, type `g`: `typed="g"`, no completion (Chrome completes `ithub.com`). Real case: ⌘L on a page whose address starts with the letter you type (hero bar strips the scheme; the sidebar bar keeps `https://`, so `h`). Fix: `inline.ts` `fieldChange` gets the selection before the change; replacing a non-empty selection with ≥ 1 inserted character is typing (Chrome: caret after > selection start), not deleting. Files: `inline.ts`, `Omnibox.tsx` `onChangeText` (~268), `inline.test.mjs`.
   **Fixed 2026-10-08:** `fieldChange` takes the selection before the edit and the caret after it (Chrome's rule: deletion only when the field shrank and the caret ended at or before the old selection start). RN delivers the new caret before the text, so `Omnibox.tsx` keeps the previous selection (`selectionBefore`, updated by every selection event, `setSelection` and the completion echo). A selection that doesn't explain the edit falls back to the text. Live (real keys): `gi`, ⌘A, `g` gives `typed=g` and the completion `ithub.com` (before: none); ⌘L on the hero bar now selects the completion too (it selected only `typed`, so the next key left `thub.com` in the field). The stale selection the audit saw was the focus itself: focusing a field that isn't being edited reports AppKit's select-all and then RN `reactFocus`'s caret at the end (`NSNotFound` clamp), after the selection the bar applies, so the first key after ⌘L (hero) or after opening the panel on a page read as a deletion. `Omnibox.tsx` `focusField` ignores those two reports; live: hero ⌘L then `g`, and the panel opened on `localhost:3000/` then `g`, both complete.

Pure: `fieldChange("", "", "github", [])` → `suppress:false`. Fix: `fieldChange`: a change that adds more than one character at once (or replaces a selection with more than one) is a paste: `suppress: true`; since `suppress` is per change, the next typed character re-enables inline like Chrome. Verify ⌘V newline handling at the same time (Chrome `SanitizeTextForPaste` joins lines with a space; only the context-menu path does that here, `Omnibox.tsx:239`).
   **Fixed 2026-10-08:** `fieldChange`: an edit that puts in more than one character at once (code points) sets `suppress` for that change only.
