# Speed, 0.2.25 → 0.2.26

The 0.2.26 release gate, 2026-10-05: the 0.2.25 export against the 0.2.26 export (built from be61ced4, the tagged
commit), one Apple Silicon Mac, hidden instances, both apps interleaved run by run in one `native-bench.mjs` process
(docs/perf/README.md). Medians, with min–max and the number of runs. Both apps share NATIVE_API_VERSION 6 and ran
0.2.26's bench bundle, so only native code differs.

A first attempt hung: the display was off (pmset, 12:07–13:45), so windows got no frames and a launch never painted;
it was discarded. 0.2.26 was published, at the owner's request, after the full round below and before the rerun.

The full round is the same or better (tab switch 34 → 27 ms, idle CPU with 20 tabs 1.33 → 1.19 %). In the idle rerun
(4 runs, second table), 0.2.25's runs were steady while three of 0.2.26's had wakeup spikes in the browser and GPU
processes (browser up to 9.1 /s against 4.2–4.6, GPU up to 7.3 /s against 0.7–0.8; idle CPU with 20 tabs up to
2.17 %). The owner was using the Mac during that round. A follow-up (16 more interleaved runs, 424bc9ee) found it was
noise: the bench's instance window was frontmost on screen, so the owner's pointer moving over it woke the app, by
about 2 wakeups/s in both versions; with the owner away the two match (1 tab 7.2 → 7.0 /s, 20 tabs 28.7 → 29.0 /s,
GPU 0.8 / 0.7 in both), and no thread is busy in 0.2.26 that isn't in 0.2.25. native-bench now records owner input
per idle window, so a gate can tell input from a regression.
